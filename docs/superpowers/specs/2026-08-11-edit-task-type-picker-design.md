# 编辑任务类型选择框设计

日期：2026-08-11  
状态：已确认，待实施

## 目标与边界

将编辑任务弹框的 Notion `select` 类型字段由原生 `Menu` 替换为与新建任务一致的可输入筛选下拉框。左侧输入区用于显示与筛选类型，右侧为带分隔线的固定下箭头；内容超过弹框高度时可向下滚动。

本次不改：`TodoListViewModel.editingPriority` 的绑定、`choiceField.options` 的 Notion 数据来源、`saveTaskEdit()` 请求、编辑标题/时长校验、类型颜色映射，或新建任务弹框。

## 交互与视觉

1. 编辑类型字段沿用新建任务的圆角白色输入框、尺寸、焦点蓝色边框与 34pt 分区下箭头。
2. 点击输入区或下箭头展开列表；输入时按忽略首尾空格、大小写的规则筛选已有 Notion 类型。
3. 展开列表包含“未选择”、类型颜色圆点、当前选择的勾选标记和无匹配空状态；点击选项或“未选择”后更新 `editingPriority` 并收起列表。
4. 进入编辑弹框时，输入区显示已有类型；关闭列表时恢复当前选中类型的名称。
5. 列表使用表单卡片内的正常布局；当列表和底部按钮总高度超过卡片最大高度时，整个编辑卡片纵向滚动，按钮不会被覆盖或裁切。
6. 保存进行中时，类型输入、下箭头与列表不可操作。

## 组件与数据流

在 `ContentView.swift` 的 `EditTaskFormCard` 内新增私有展示状态：查询文本、展开状态与输入焦点。选项由已有 `TaskChoiceField.options` 过滤得出，选择结果仍通过 `$viewModel.editingPriority` 写回。

`类型选择 → TodoListViewModel.editingPriority → saveTaskEdit() → NotionRepository.updateTask(...)` 的既有流程不变；不增加 ViewModel、持久化、网络调用或 Notion API 契约。

## 测试与验证

1. 扩展源码 smoke 契约，先验证编辑表单尚未具备搜索输入、固定下箭头、筛选、列表高度及外层滚动，从而得到预期失败。
2. 以最小 SwiftUI 改动实现后，重新运行 smoke、全量 `swift test` 和 Debug build。
3. 启动应用并实际编辑任务：打开类型、筛选、选择、清空、展开较长列表后向下滚动、取消；不执行保存到 Notion 的写操作。

## 风险与回滚

风险是编辑卡片同时存在类型列表与保存按钮时的高度竞争；通过复用新建表单的卡片高度上限和纵向滚动来保持内容可达。回滚 `EditTaskFormCard` 的类型选择与滚动容器即可恢复原生 `Menu`，不会改变任何已保存的任务数据。
