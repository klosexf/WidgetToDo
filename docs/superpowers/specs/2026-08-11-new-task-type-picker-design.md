# 新建任务类型选择框设计

日期：2026-08-11  
状态：已确认，待实施

## 目标与边界

将新建任务弹框的类型（Notion `select`）由原生 `Menu` 外观替换为可输入筛选的下拉选择框。用户可点击输入区域或右侧下箭头展开选项，也可直接输入以筛选相关类型。

本次不修改：`NewTaskViewModel.priority` 的绑定、`choiceField.options` 的 Notion 数据来源、任务创建请求、类型字段的颜色映射、编辑任务弹框，或其他新建任务字段。

## 交互与视觉

采用已确认的“明确分区”方案：

1. 类型字段保持与标题、日期、时长一致的圆角白色输入框、边框、字号和高度。
2. 左侧为带放大镜的可编辑输入区；无选择且为空时显示“搜索或选择类型”。
3. 右侧固定为窄的下箭头按钮，并以一条浅色竖线与输入区分开；箭头只承担展开/收起选项的动作。
4. 点击输入区或箭头后，在字段下方显示圆角浮层列表。输入时列表实时过滤 `choiceField.options`；过滤不区分大小写并忽略首尾空格。
5. 列表顶部提供“未选择”，用于清除当前类型；其他选项显示与任务列表相同的类型颜色圆点和名称。单击选项后写入 `viewModel.priority` 并收起列表。
6. 已选择状态在输入区显示同色圆点和选项名称；清空输入或选择“未选择”后恢复占位文案。
7. 没有匹配项时浮层显示简短的空状态提示，不创建新的 Notion 选项。
8. 保存任务期间，输入区、箭头和选项列表均不可操作。

## 组件与数据流

仅调整 `WidgetToDo/WidgetToDo/NewTaskFormCard.swift` 的私有 `TaskChoicePicker`。组件新增私有的筛选文本、展开状态与焦点状态；`selection` 仍双向绑定到 `NewTaskViewModel.priority`。可见选项由已有的 `TaskChoiceField.options` 纯计算得出。

类型选择 → `selection` → `NewTaskViewModel.priority` → 既有 `submit()` / `NotionRepository.createTask(...)`。不引入新的 ViewModel、持久化字段、网络请求或 Notion API 契约。

## 错误处理与可访问性

输入筛选没有校验错误；无匹配时仅显示本地空状态。保留类型名称作为辅助说明，并让输入框、箭头及每个选项有明确的可访问标签。焦点时沿用新建任务表单现有的蓝色边框反馈。

## 测试与验证

1. 先扩展 `NotionFloatCoreSmokeTests`：断言类型组件包含搜索输入、固定 `chevron.down`、筛选逻辑、清除入口、与 `selection` 的绑定；先运行并确认旧实现失败。
2. 实现最小 UI 改动，再运行 smoke、`swift test` 和 Xcode Debug build。
3. 实际启动 app：点击「+」→ 打开类型 → 输入筛选 → 选择类型 → 再打开并清除 → 创建任务；核对样式、菜单位置和 Notion 写入结果。

## 风险与回滚

风险是自定义浮层在窄弹框或输入焦点变化时提前关闭。实现会将列表限制在表单卡片宽度内，并且只在显式选择、取消或保存时收起。回滚只需恢复 `TaskChoicePicker` 的原生 `Menu` 实现；不会影响已创建任务或 Notion 数据。
