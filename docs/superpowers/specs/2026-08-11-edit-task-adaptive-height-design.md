# 编辑任务弹框自适应高度设计

**日期：** 2026-08-11  
**状态：** 已选择方案 A，待规格确认后实施

## 目标

让编辑任务弹框在类型列表关闭时贴合实际字段和按钮高度，移除保存按钮下方的无效留白；当类型列表展开或系统字体放大导致内容超过安全上限时，继续使用现有 5 pt 极细纵向滚动条。

## 非目标

- 不调整新建任务弹框的高度策略。
- 不改变任务标题、时长、类型选择、取消/保存、Notion 写入或字段 Binding。
- 不改变滚动条外观、宽度或拖拽行为。

## 方案比较与选择

- **A（已选）：内容自适应 + 最大高度。** 编辑表单按内容测量高度，外层卡片保持 `242...376 pt` 的安全区间。内容不足上限时收紧；超出时固定在上限并通过极细滚动条访问全部内容。
- B：固定紧凑高度。实现简单，但本地化文本、动态类型列表和辅助功能字体变化后容易再次出现留白或拥挤。
- C：保持当前固定最大高度。能预留类型列表空间，但普通编辑状态下视觉留白明显。

## 设计

### 布局行为

`EditTaskFormCard` 继续使用当前卡片宽度与 `minHeight` / `maxHeight` 约束。变化在于其 AppKit 承载滚动视图需要向 SwiftUI 提供内容的有效固有高度：

1. 类型列表关闭时，表单内容的拟合高度成为卡片首选高度，卡片收紧到按钮下方。
2. 类型列表展开或内容变高时，滚动容器重新测量 `NSHostingView` 的拟合高度。
3. 拟合高度超过 `cardMaxHeight` 时，SwiftUI 外层高度保持在 376 pt，`NSScrollView` 的文档高度继续大于可视区域，保留纵向滚动。
4. 拟合高度低于 `cardMinHeight` 时，卡片仍使用 242 pt，避免极短状态造成不稳定跳变。

### 组件边界

为避免影响新建任务弹框，`SlimFormScrollView` 新增一个仅决定布局协商的参数，例如 `usesContentHeight: Bool = false`。只有编辑任务传入 `true`。内部 `HostingScrollView` 在该模式下根据 `NSHostingView.fittingSize.height` 提供固有高度，并在根视图更新或容器重新布局后失效并重新计算该高度。

该参数不接触表单字段或 ViewModel 状态；类型列表的开关仍由现有 SwiftUI 状态驱动，变化通过 `updateNSView` 进入共享容器。

## 错误与边界

- 文档宽度在首次布局前为零时，不发布错误高度；维持当前布局并等待后续 `layout` 重测。
- 高度计算最小值为 1 pt，避免 `NSHostingView` 临时零高度破坏滚动文档。
- 使用既有 `.frame(minHeight:maxHeight:)` 作为视觉与可达性的边界，不引入手写固定编辑弹框高度。

## 验证

1. smoke 合约先在当前代码失败，要求编辑表单显式启用内容高度模式，且共享容器提供可失效的内容固有高度。
2. 编译后 smoke 通过，并执行 `swift test`。
3. 执行 Xcode Debug 构建。
4. 在已配置应用中手测：普通编辑时保存按钮下无大块留白；展开较多类型后可滚动到取消/保存；关闭类型列表后弹框重新收紧；取消不写入 Notion。

## 风险与回滚

- 风险：AppKit 与 SwiftUI 之间的高度协商可能在首次显示时需要一轮布局刷新。实现仅在布局/更新阶段失效固有高度，避免持续循环。
- 回滚：移除编辑表单的内容高度参数即可回到当前固定高度策略，不影响数据、任务编辑或新建任务弹框。
