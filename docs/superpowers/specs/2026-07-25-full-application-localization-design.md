# 全应用自有文案本地化设计

## 目标

让 WidgetToDo 所有由应用生成的可见文字，在简体中文、English、Français 之间即时切换。`Language` 标签和三种语言选项的原生名称保持固定。

## 范围

纳入：欢迎／初始化／设置、帮助弹窗、菜单栏、待办与日记面板、日期与空状态、同步横幅、加载与错误提示、任务表单、删除确认、Toast、迷你胶囊、无障碍标签和工具提示。

不纳入：用户输入的任务标题和日记正文、Notion 属性名与优先级值、Notion 返回的原始详情、URL、系统图标名、预览夹具中的用户数据。

## 架构

- `AppText.Key` 是所有应用自有文案的唯一目录，并为三种 `AppLanguage` 提供完整译文。
- 不带动态参数的状态保存 `AppText.Key`；带参数的状态保存 `AppMessage(key, arguments:)`。
- SwiftUI 与 AppKit 在显示边界使用 `LanguageStore` 解析键或消息。语言变更只更新显示，不触发 Notion 请求。
- 错误信息只翻译应用生成的上下文，例如“任务同步失败”；Notion 服务器返回的详情作为参数原样保留。

## 迁移策略

1. 先补齐目录和三语测试，再迁移 Core 验证与 ViewModel 的动态状态。
2. 迁移所有静态界面、菜单、帮助、表单、确认框和迷你模式文案。
3. 为源代码审计建立白名单，阻止新的应用自有文案以字面量进入视图。
4. 在三种语言下验证切换、重启恢复和已显示状态的即时刷新。

## 验收标准

- 所有 `AppText.Key` 在中英法均有非空译文。
- 应用自有文本不以中文／英文／法文字面量直接出现在显示代码中，白名单项除外。
- 已显示的日期、状态、横幅、提示和表单文案在切换语言后立即更新。
- `swift test --disable-sandbox`、smoke 审计和 Debug 构建均通过；桌面手测覆盖欢迎页、设置、待办、日记、表单、Toast、迷你模式和菜单栏。

## 风险与回滚

本次不改变 Keychain、缓存、Notion API 或用户内容。若需回滚，可回退本次本地化提交；保存的语言偏好和业务数据不受影响。
