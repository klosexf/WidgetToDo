# 编辑任务弹框固定头尾与自适应滚动设计

**日期：** 2026-08-12  
**状态：** 方案 A 已确认，待用户审核本文档

## 目标

消除编辑任务弹框在类型列表关闭时取消/保存按钮下方的空白；仅在用户展开类型列表或内容实际超出上限时增加高度，并将超出的字段及选项限制在弹框的中间滚动区域。弹框标题和取消/保存操作区须始终可见，且弹框不得越过其 376 pt 可视上限。

## 非目标

- 不改变新建任务弹框、任务字段、ViewModel Binding、保存/取消语义或 Notion 请求。
- 不改变 5 pt 极细滚动条的外观、滚轮、触控板或拖拽语义。
- 不改变弹框宽度、字段尺寸、色彩或类型筛选行为。

## 已确认方案：A（内容自适应 + 最大可视高度 + 固定头尾）

`EditTaskFormCard` 分为三个垂直区域：固定标题、可滚动表单内容、固定操作区。折叠时滚动区采用内容的实际拟合高度，因此卡片紧贴最后一个操作按钮；展开类型列表后，滚动区依内容增长，直至卡片可视高度达到既有 `NewTaskFormMetrics.cardMaxHeight`（376 pt）。超过该高度的内容继续保留在 AppKit 文档视图中，用户通过中部区域内的极细滚动条访问它。

类型下拉的收展使用约 0.22 秒 `easeInOut` 动画，驱动滚动区高度与卡片高度平滑过渡。折叠时不显示滚动条；溢出时只在中部内容区显示滚动条，标题和取消/保存不参与滚动。

## 组件与数据流

1. `EditTaskFormCard` 把当前标题和底部按钮从 `SlimFormScrollView` 的文档内容中拆出，保留当前字段与按钮动作不变。
2. 中部的 `SlimFormScrollView` 承载任务、时长、能力维度及已展开的类型选项；使用内容高度协商与 376 pt 上限。
3. `HostingScrollView` 继续把完整 `NSHostingView` 高度作为文档高度，只限制自己的固有可视高度，保证滚动范围完整。
4. 现有 `isTypeOptionsPresented` 是唯一的展开状态来源；该状态变化触发中间文档重测和高度动画，无需新增持久化状态或修改 ViewModel。

## 高度规则

| 状态 | 卡片高度 | 滚动范围 | 固定可见区域 |
| --- | --- | --- | --- |
| 类型列表关闭且内容较短 | 标题 + 内容 + 操作区的最小必要高度（至少 242 pt） | 无 | 标题、所有字段、取消/保存 |
| 类型列表展开且未超上限 | 随内容增长，最多 376 pt | 无 | 标题、所有字段、取消/保存 |
| 展开或辅助功能字体导致超上限 | 固定为 376 pt | 仅中间字段/类型选项区 | 标题、取消/保存 |

## 边界与错误处理

- 首轮布局前若中部宽度为零，延后发布新的拟合高度，避免临时零高度造成跳变。
- 完整文档高度必须始终保留，不能将它截为可视上限，否则底部字段和选项不可达。
- 高度变化设置小阈值，避免 AppKit 与 SwiftUI 在亚像素差异上反复失效布局。
- 现有 `.fixedSize(horizontal: false, vertical: ...)` 不得重新用于 AppKit-backed 滚动容器，因为它会造成无效固有尺寸。

## 验证

1. 为 smoke 测试添加失败契约：编辑表单必须包含独立的固定标题、内容滚动区和固定操作区，并对 `isTypeOptionsPresented` 的高度变化应用显式动画。
2. 实现后运行 `swift run NotionFloatCoreSmokeTests`、`swift test` 和 Debug `xcodebuild`。
3. 在已配置应用中手测：
   - 普通编辑时，保存按钮下没有空白。
   - 展开类型时卡片平滑增长。
   - 超过上限时标题与取消/保存始终显示，只有中部区域滚动，所有类型与字段均可达。
   - 收起类型后卡片平滑收紧；取消不写入 Notion。

## 风险与回滚

- 风险：拆分固定区域后，AppKit/SwiftUI 的高度协商需跟随中间内容更新；用既有 0.5 pt 测量阈值防止循环。
- 回滚：恢复编辑表单为单一滚动文档结构并移除对应动画/测试即可回到当前行为；不涉及任务数据或 Notion 配置。
